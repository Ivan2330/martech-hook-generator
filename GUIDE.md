# Гайд: робимо ДЗ3 через агентів у Claude Code

Мета подвійна: здати ДЗ і натренуватись працювати з агентами перед батлом. Ти тімлід, агенти виконують, ти перевіряєш.
Загалом ~5–6 год. Промпти нижче можна копіювати як є.

---

## 0. Підготовка (10 хв)
1. VS Code → File → Open Folder → `C:\Users\user\Code\socklock-hw3`.
2. Відкрий Claude Code (розширення або термінал: `claude`).
3. Введи `/agents` — маєш побачити 4 субагенти: `market-researcher`, `egp-analyst`, `code-reviewer`, `grader`. Глянь їхні файли в `.claude/agents/`, щоб розуміти, що кожен робить.
4. Python-оточення:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
5. Скопіюй `.env.example` → `.env` і встав свій `ANTHROPIC_API_KEY` (якщо нема — MVP має працювати в демо-режимі).

**Що тренуєш:** CLAUDE.md як пам'ять проєкту, субагенти як команда.

---

## 1. Паралельний ресерч (запусти і не чекай, 15–20 хв у фоні)
Промпт:
> Запусти паралельно двох субагентів: market-researcher (build vs buy → docs/build-vs-buy.md) і egp-analyst (перевірка всіх цифр → docs/egp.md). Поки вони працюють, переходь до плану MVP.

**Що тренуєш:** паралельність і чистий контекст: головна сесія не забивається пошуком.

---

## 2. План MVP у plan mode (15 хв)
Увімкни plan mode (**Shift+Tab** двічі, поки внизу не з'явиться «plan mode»). Промпт:
> Прочитай CLAUDE.md і examples/. Склади план MVP за специфікацією: які файли, які функції, як дані йдуть від вставленого скрипта до карток з варіантами, де демо-режим, де пам'ять правил. Код поки не пиши. Пиши максимально просто — я маю пояснити кожен рядок.

Прочитай план. Задай 2–3 питання («навіщо цей файл?», «чи можна простіше?»). Потім погодь.

**Що тренуєш:** спершу гіпотеза, як має працювати, потім код (пайплайн з лекції Михайла).

---

## 3. Пишемо MVP (1,5–2 год)
Йди маленькими кроками, після кожного запускай:
1. > Напиши prompts/system.md і generator.py. Few-shot з examples/, відповідь суворим JSON. Покажи, як запустити з терміналу на winner_01.
2. > Додай checks.py: dedupe_similar() на difflib і compliance_flags(). Напиши тести в tests/.
3. > Додай memory.py: 👍/👎 перетворюються на одне коротке правило, ліміт ~1000 токенів, старі правила випадають.
4. > Зроби app.py на Streamlit: текстове поле, кнопка Generate, картки варіантів з angle, прапорцями і кнопками 👍/👎.
5. > Додай демо-режим: якщо нема ANTHROPIC_API_KEY, повертай examples/demo_output.json. Збережи туди реальну відповідь з останнього запуску.

Запуск: `streamlit run app.py`.

**Опційно (тренуєш хуки):** попроси
> Налаштуй хук у .claude/settings.json: після кожної правки .py файлу запускати python -m pytest -q.

## 5. Документ до 3 сторінок (1 год)
> Прочитай CLAUDE.md, docs/egp.md і docs/build-vs-buy.md. Напиши docs/homework3.md до 3 сторінок (~1 300–1 500 слів), українською, кроки 1–4: 1) вибір проблеми + таблиця «чому не інші» з коефіцієнтом EGP/ефорт + абзац «Що я помітив у цифрах»; 2) EGP у трьох сценаріях з формулами і явними припущеннями + ефорт; 3) build vs buy; 4) problem statement БЕЗ жодного слова про рішення (хто, проблема, доказ, скільки EGP) і пітч для Head of Marketing (рішення одним реченням, ефект, вартість, чому будуємо, ризики + пілот 2 тижні на 2 дизайнерах, цифра зупинки, конкретний запит). Простою мовою, без води.

Потім перенеси в Google Docs (скопіюй Markdown або відкрий файл через Google Docs). Перевір, що вміщається в 3 сторінки.
